# IP 人设解析器

## 零、为什么必须有这一层

本制片组服务**多个 IP**。每个 IP 的字数、结构、语气、节奏、CTA、流程都不同——用同一套参数写，所有 IP 都会失去辨识度。

所以任何产出开始前，**第一件事是把「IP 名」解析成一张卡**。没有卡就不许动笔。

> 铁律：**先解析 IP，再干活。** 严禁跳过本步直接用默认写法开写。

## 一、解析优先级（严格按顺序）

1. **Notion 人设卡（最高优先级）** — `内容/_IP人设卡/` 目录下 `IP卡-<IP名>`
   检索方法：用 `mcp__notion__notion-search` 搜 `IP卡-<IP名>`；搜不到再搜 `内容/` 定位目录后取子页面。
   **理由**：Notion 上的卡由编导维护，改一行所有人下次调用立即生效，不需要重发专家包。这是团队能各自更新、老板能随时同步的关键。
2. **内置兜底卡** — `references/` 下的卡（当前含香港胡子哥、TC李老師打样稿）
   Notion 检索失败或该 IP 尚未建卡时使用。**兜底卡可能过时，使用前必须向用户确认一次。**
3. **都没有** — 停止产出，向用户索取以下最少字段，不许自行推断：
   一句话定位 / 受众 / 字数区间 / 结构 / 语气三条 / 明确禁用项

## 二、IP 名解析规则

**先查 `references/ip-registry.md` 的别名注册表**——团队里每个人叫法都不一样（爱酱 / 于倩文 / Ashley 是同一个人），不查表必然解析错。

| 用户输入 | 处理 |
|---|---|
| 精确匹配标准名或别名 | 直接取该卡 |
| 句子里含某个别名（「给爱酱写一版」） | 子串命中 |
| 繁简/错拼（老师↔老師、Ashely↔Ashley） | 容错归一 |
| 命中多个或模糊 | **列出候选让用户确认**，严禁自行挑选 |
| 一个都没命中 | 停止产出，问是不是新 IP；确认后提示建卡并回写注册表 |
| 「全部 IP」「所有 IP」 | 逐个 IP 分别出题（各按自己的定位与客群），**不做观点翻译**；或先问用户 |
| 未指定 IP | **必须先问**，禁止默认给某一个 IP |

⚠️ **检索 Notion 时用「Notion 目录名」，不要用账号名。** 有 4 个 IP 两者对不上（如湾区E姐的目录叫「吳貽玲」），用账号名搜不到。对照表见注册表。

## 三、人设卡标准字段（建新卡时照此填）

卡要精炼——**目标是一张卡 ≈ 一屏，能被完整塞进上下文**。历史稿作为可选深挖，不整本喂。

| 字段 | 必填 | 说明 |
|---|:--:|---|
| 一句话定位 | ✅ | 「XX 是什么样的人」，决定所有输出的底色 |
| 身份锚点 3–5 条 | ✅ | 可信度来源；**必须真实，不可虚构** |
| 受众画像 | ✅ | 细分人群 + 他们正在做的选择 |
| 内容配比 | ⭕ | 有数据就填（如月度 20 条各类型占比） |
| 字数区间 | ✅ | **决定成稿长度的硬参数**。**全包统一：≤700 字（硬上限），无例外**——卡上若写着别的规格，一律按 700 上限执行，不要报冲突 |
| 结构 | ✅ | 如「开头→三层递进→最强转折→强收尾」 |
| 前 3 秒钩子 | ✅ | 可用范式 + 明确禁用范式 |
| 节奏要求 | ⭕ | 如「每 30 秒一个新信息点」 |
| 语气与用词 | ✅ | 三条以上；必须含「必用」和「禁用」 |
| 常用句式 | ⭕ | 该 IP 的标志性表达 |
| 结尾 CTA | ✅ | 固定品牌语，或按内容类型分流 |
| 港险承接方式 | ✅ | 「逻辑相关才提」还是「月度 X% 更直接」 |
| 流程开关 | ✅ | 全包统一：**先出 10 选题 × 5 立意 → 用户勾选 → 写稿**，无例外；此字段只记录该 IP 的附加工作流（如 Eva 语音转稿、Tina 直接 copy paste） |
| 硬禁用 | ✅ | 违禁词、失效标题、风格雷区 |

> 卡写得笼统，输出就笼统。这一步省不得。

## 四、解析后必须产出的东西

把卡压缩成下面这段「注入块」，后续所有角色都以它为准：

```
【当前 IP】<名字>
定位：<一句话>
受众：<细分人群>
字数：<区间>
结构：<步骤>
钩子：<可用范式> ｜ 禁用：<范式>
语气：<三条>
必用：<词/句式> ｜ 禁用：<词/句式>
CTA：<结尾方式>
港险：<承接方式>
流程：先出 10 选题 × 5 立意 → 用户勾选 → 写稿（附加：<无 / Eva 语音转稿 / Tina 直接发布>）
禁用：<硬红线>
```

**这个注入块必须完整写进派发给每个成员的任务 prompt 里**——成员看不到当前对话，没有它就只能凭印象写，结果必然串味。

- 卡上若仍写着旧规格，**按 ≤700 执行**：不要报「与全局冲突」，不要按卡放宽，也不要为此停下来问用户；
- 建议成稿落在 **620–700 字**（写太短信息量不足，可以顶着 700 上限写）；

新增 IP 时：在 Notion `内容/_IP人设卡/` 建 `IP卡-<标准名>`，**不需要改专家包**；同时把别名补进 `ip-registry.md`。这是本架构最重要的特性。

## 六、给多个 IP 出题时的注意事项

一次给多个 IP 出题时，**每个 IP 按自己的定位与客群分别出题**，不是同一个题换名字：

- ✅ 根据各 IP 的受众痛点，找各自的保险理念结合点
- ❌ 一份通用清单让所有 IP 共用
- ❌ 同一个热点硬套到定位不相关的 IP 身上（过不了相关性闸门）
- ❌ 用 A 的字数写 B（这是最常见的翻车点）

派发时每个 IP 一个独立成员实例，各自拿到**自己那张卡**，互不参照。
