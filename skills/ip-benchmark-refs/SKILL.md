# 对标博主蒸馏库 · 使用规范

> 库是**参考机制**用的，不是**搬运内容**用的。这个库自己就写着「不借用他人履历，不编造案例，不照抄原句」——
> 本 skill 把这句变成硬约束。

一句话蒸馏 / 人设结构 / 受众与选题地图 / 标题机制 / 表达与视觉 / **数据给出的边界** /

### 两个库的字段

**博主档案**：博主 / 平台 / 内容领域 / 目标受众 / 一句话蒸馏 / 可借鉴机制 / 创作应用 /
证据完整度 / 详情样本数 / 可见标题数 / 待补证据 / 研究状态 / 主页 / 采样日期

**选题实验库**：选题 / 主题 / 目标受众 / 切入机制 / 内容性质 / 创作状态 / **需要的真实素材** /

> `证据完整度` 目前普遍是「仅主页与标题」或「含详情与部分画面」，**没有一位有完整逐字稿**。
> 所以：**不许声称在对标「他们的口播语言」**，能对标的只是「选题角度 + 标题机制 + 结构方法」。

## 二、三条铁律（违了就是废稿）

1. **不借履历** —— 对标博主的学历、职位、年薪、团队规模、客户故事，**一个字都不能挪到 IP 身上**。
   他的履历只用来解释「为什么这种讲法对他有效」，不是素材来源。
2. **不抄原句** —— 标题、金句、比喻、句式都不照搬。只借**机制**（见第四节），
   落到具体文字必须是这个 IP 自己会说的话。
3. **不把标题当正文依据** —— 库里明确写了「标题不能替代完整口播」。
   看到他的标题结构，只能推「他用了什么机制」，**不能推「他的正文是怎么论证的」**。

另外两条纪律：

- **一次表现 ≠ 稳定规律**。点赞高只说明这一条跑得好，不能写成「这套选题已跑通」。
- **未取得的数据不当 0**。播放/转化空着就是空着，不许替它算互动率或下结论。

## 三、怎么按 IP 自动挑对标博主（每次现场判断，不存固定对照表）

**每次**给某个 IP 做选题或写稿时，按下面四步现场挑，**不许凭印象固定「某某 IP 就一直对某某博主」**：

1. **读 IP 卡** —— 定位、客群画像、内容配比、禁用表达（`ip-persona-resolver`）
2. **按 `内容领域` 初筛** —— 库里 11 个领域：中年转型 / 职场成长 / 香港发展 / 港险 / 教育家庭 /
   宏观财经 / 商业分析 / 科技AI / 家庭财富 / 港漂生活 / 销售招募
3. **按 `目标受众` 与 `创作应用` 复核** —— `创作应用` 字段已经写明「适合迁移成什么」，
   对得上才留。受众对不上（比如 IP 客群是育儿妈妈，博主受众是中年高管）→ **剔除**
4. **定 1–3 位，并写一句为什么选** —— 超过 3 位就说明没筛干净

**配不上就直说。** 库里现在 6 位都是小红书、集中在财经/转型/港漂，
如果某个 IP 的赛道（如医疗健康、女性育儿）在库里找不到贴合的人，
**必须明确告诉用户「本库暂无贴合该 IP 的对标博主」**，禁止硬凑一个相关性弱的。

## 四、11 种可借鉴机制（真正要借的就是这个）

| 机制 | 怎么用 |
|---|---|
| **身份落差** | 把「身份标签」放进具体挫折里（学历/职位/年龄 × 处境） |
| **认知重估** | 给一个熟悉词一个新判断（长期主义、体面、最优路径……） |
| **人群困境** | 点名人群 + 处境 + 代价，快速筛出目标读者 |
| **数字步骤** | 两道坎 / 五条路 / 三种损失 —— 让内容显得有边界、可消化 |
| **个人选择** | 用「我为什么做这个决定」承载观点（叙事而非训话） |
| **热点反差** | 抓热点里看似矛盾的现象，再做解释 |
| **量化比较** | 统一金额与期限，比较费用与情景，不做收益承诺 |
| **场景冲突** | 用具体家庭/决策场景把抽象议题落地 |
| **生活记录** | 真实过程与账本，比结论更有代入感 |
| **问题清单** | 把「该问什么」列清楚，替读者做筛选 |
| **概念翻译** | 先定义、再举例、再说边界，减少铺垫 |

> 用机制时**必须写下用的是哪一个**，便于用户判断我们借得对不对。

## 五、结构映射：库的链 ↔ 我们的五层结构

库建议的正文链是「具体困境 → 真实经历 → 判断变化 → 原因解释 → 行动建议」。
它和我们硬规定的五层结构**不是二选一，是同一件事的两种说法**：

| 库的链 | 我们的五层 | 写法要点 |
|---|---|---|
| 具体困境 | **钩子**（45–55 字） | 第一句就是目标读者的场景/冲突，不先堆履历 |
| 真实经历 | **铺垫**（120–145 字） | 只用 IP 自己真实、与问题相关的信息 |
| 判断变化 + 原因解释 | **主体**（325–375 字） | 说明哪个事实让旧判断失效，并区分适用条件 |
| 判断变化的抬升 | **升华**（58–68 字） | 从个案抬到可迁移的判断，**别把个案说成所有人的命运** |
| 行动建议 | **引导**（45–55 字） | 一项低成本可执行动作 + CTA |

**时长以本包为准**：库里写「约 90 秒」，我们硬规定 **≤700 字（≈1 分 40 秒）**，一律按 700 执行。
库里那套「两行封面文案 + 一个评论问题」：封面文案**不产出**（封面已改外部工具）；
评论问题**并进结尾 CTA**，不单独列。

## 六、选题实验库怎么用

### 字段含义

| 字段 | 怎么用 |
|---|---|
| `主题` / `目标受众` | 第一道筛：跟这个 IP 的定位、客群对不对得上 |
| `切入机制` | 直接用，是这条选题的骨架 |
| `需要的真实素材` | **第二道筛，最容易漏**：IP 有没有这个真实经历 |
| `验证假设` | 这条选题想验证什么，写进候选理由 |
| `创作状态` | 现在基本都是「待验证」——**引用时必须标明** |
| `内容性质` | `原创衍生` = 库里新拟的题（可以拿来用）；`原作拆解` = 拆原文的（只能当机制参考，不能当自己的题） |

### 素材缺口检查（硬闸门）

选题实验库每条都有「需要的真实素材」。**IP 拿不出这个素材，这条就不能直接写**，三条出路：

1. IP 真实有的类似经历 → 换成他自己的，写明换了什么
2. 没有 → 标 **【需 IP 提供素材：XXX】** 交给用户，**不许替他编**
3. 既没有也不打算要 → 丢弃

> 这一条是本库接进来后**最容易出事的地方**：库里那些「做了十年管理第一次独立报价」
> 「高学历新人第一次做销售」的题写得很好，但 IP 没有这段经历，写出来就是编造。

### 与抓热点合并出题

W1 现在有**两个选题来源**，两边合并后再过闸门：

1. **互联网抓热点**（原有）
2. **对标库选题 + 博主选题地图**（新增）

合并后仍然过原来的**相关性闸门**，并新增两道：

- **IP 匹配闸**：`内容领域` / `目标受众` 与这个 IP 对得上吗？
- **素材缺口闸**：IP 拿得出「需要的真实素材」吗？

> 库里 23 条主要是「中年转型 / 职业能力 / 家庭财富 / 商业分析 / 科技AI」，
> 与港险强相关的只是一部分。**不要因为库里写着就都要用**。

## 七、接保险的尺度（2026-09-23 用户拍板）

分三类，**必须在选题卡上标清楚属于哪类**：

| 类型 | 要不要接保险 | 例子 |
|---|---|---|
| **保险专业向** | **必须接** —— 落不到保险知识点或理念就丢弃 | IP 主航道内容（港险机制、核保、税务、传承） |
| **中年转型 / 职业类** | **可挂招募向** —— 接「转行做港险」的招募线索 | 大鹿在路上那条线：职场困境 → 职业选择 → 香港事业 |
| **流量向 / 人设向** | **不必接保险** —— 但要标明「本条不带保险落点」 | IP 卡里的 20% 泛生活、10% 热点实验 |

> 判据：这条题是**给客户看的**还是**给流量/招募看的**？
> 前者必须落到保险，后者可以不落，但不许假装它落了。

## 八、输出格式：对标摘要

做选题或写稿时，**先给一段简短的对标摘要**，再进正题：

```
【对标参考】
· 选了：<博主名> — 为什么选（一句）
· 机制：<从 11 种里挑 1–3 个>
· 借什么：<只借结构/机制，具体说明>
· 不借什么：<明确划出履历、原句、观点>
· 证据边界：<该博主 `证据完整度` 与 `待补证据` 的一句话提醒>
· 素材缺口：<需要 IP 提供但还没有的东西；没有就写「无」>
```

对话里给这段就够；**不必**把库里的原文抄回来。

## 严禁

- ❌ **借用对标博主的学历 / 职位 / 年薪 / 团队成绩 / 客户故事**（最严重的一条）
- ❌ **照抄原句、复刻标题**，或把他的观点当成这个 IP 的观点
- ❌ 拿库里的**标题**当「他的正文怎么论证」的依据
- ❌ **把对标博主当选角替代品**：挑不到贴合的就说没有，不许硬凑相关性弱的
- ❌ 把「待验证」选题说成「已验证有效」，或用点赞/播放数据证明「这套跑通了」
- ❌ 数据缺失时当 0 处理，或替它算互动率
- ❌ 声称在「对标他的口播语言」——库里没有完整逐字稿，只能对标选题角度、标题机制、结构方法
- ❌ IP 没有「需要的真实素材」却硬写，**或替 IP 编一段经历**
- ❌ 用库里的 90 秒 / 两行封面文案改本包规格（一律 ≤700 字、五层结构、不产封面文案）
- ❌ 把固定对照表当常理：「某某 IP 就用某某博主」——**每次都要重新按定位判断**
