# 言直在线选题组（yzzx-content-studio）

> 版本 **2.8.1**（2026-09-22）。专家标识 `yzzx-content-studio`，创建后不可改。
> 版本发布规则见 `RELEASE.md`，变更历史见 `CHANGELOG.md`。

为保险自媒体 MCN 打造的内容制片团队。旗下所有 IP 做的都是**香港保险自媒体**，但客群各异、保险击中他们买点的方式也各不相同。

工作流：**定 IP → 学 ima 保险知识 → 抓网络热点 → 判相关性 → 出 10 个选题各 5 个立意（可勾选网页，支持「本轮不做」与自定义想法）→ 用户选 → 写 ≤700 字口播稿 → 合规终审 → 出标题/简介/标签 → 写入 Notion**。

## 类型

Team 型（多角色协作团队）

> **版本命名指南（x.y.z 各管什么）见 `RELEASE.md`**；专家卡片上显示的版本号即当前安装版本，可直接用于核对。

## 不在本团队范围内

**封面** —— 由外部独立工具完成，本团队只做内容。

## 最重要的设计：IP 风格不写在包里

**IP 人设卡放在 Notion（`内容/_IP人设卡/IP卡-<名字>`），不放进专家包。**

原因：专家包装在每个人自己电脑上，你改了自己那份，别人的不会跟着变。人设卡放云端后，编导改一行，**所有人下一次调用读到的就是新的**。

解析优先级：**Notion 卡 → 包内兜底卡 → 停下来问用户**。新增一个 IP 只需在 Notion 加一张卡。

> ⚠️ **现状（2026-09-22）**：**包内 `references/IP卡-*.md` 这 7 张兜底卡是当前实际在跑的卡**，
> 内容完整、可直接用；Notion 侧的独立人设卡页面位置尚未确认。
> 因此**改写法时以包内卡为准** —— 改卡 = 改包，属「流程/角色」类，要走 `release.py` 发版。

## 工作流（W0 前置自检 + 六条主流程）

| Workflow | 什么时候用 | 说明 |
|---|---|---|
| **W0 前置自检** | *每次调用自动触发* | 先提示确认 **ima + Notion 已连接授权**，用户回「都好了」才进下一步；并报出版本号供核对 |
| **W1 选题池** | 说「出选题」「这周拍什么」「选题池」+ 指定 IP | 学 ima 保险知识 → 抓热点（**含「香港故事」常备主线**，见 `ip-topic-engine` 第 6 类）→ **捞对标博主蒸馏库**（`ip-benchmark-refs`：按 IP 现场挑 1–3 位，借机制不借内容）→ **相关性闸门 + IP 匹配闸 + 素材缺口闸** → 出 10 个选题 → 每个拆 5 个立意点 → 合规预判 → 出**可勾选选题池网页**（每题可标「本轮不做」、可写自己的想法）→ **用户勾选、选立意、剔除不要的题** |
| **W2 口播成稿** | *勾选完立意后自动进入* | 按该 IP 定位写 **≤700 字** 口播稿（全包统一，无例外），五层结构 + 情绪波浪 + 信息钩子链 + **去 AI 味写作法（硬门槛）**；写前按 `ip-benchmark-refs` 对标本 IP 的对口博主（借机制不借内容） |
| **W3 合规终审** | *成稿后自动进入*，或说「查一下合规」 | 三查：事实核查 / 三平台敏感词 / 香港保险内地宣传合规 |
| **W4 发布包** | *终审通过后自动进入*，或说「出发布文案」 | 标题 10 个（≤10 字）+ 简介 5 个（20–30 字）+ 三平台标签 → 写入 Notion 文案库。**页面正文固定五个可折叠 H4 板块**（新闻来源 / 口播文案 / 标题 / 简介 / 标签），属性列保留含 **新闻来源 / 辅助链接**。**不再生成发布包 HTML** |
| **W5 素材速写** | 你**手上有现成素材**（链接 / 文案 / 文章 / 截图 / 录音转写，形式不限）并说「就拍这个」 | **先问清「这条给哪位 IP 写」** → 跳过抓热点，直接拿你的素材接保险理念 → 拆立意 → 往后同 W1 之后 |
| **W6 复盘迭代** | 你想知道**上一批内容表现如何、下批做什么**，说「复盘」「这批数据怎么样」 | 主理人自己分析（不派成员），输出哪类选题跑得好、下期建议；多 IP 时按 IP 分开看 |

> **W1 Phase 4 是不可跳过的用户决策点** —— 用户没选选题和立意，严禁进写稿。
> **宁可只给 7 个扎实的选题，也不要凑满 10 个水的。**

## 成稿规格

| 规格 | 字数 |
|---|---|
| **默认（全包统一，8 个 IP 无例外）** | **≤700 字（硬上限）**，建议落在 **620–700 字** |
| 90 秒 | 540–660 字 |
| 60 秒 | 360–440 字 |
| 30 秒 | 180–220 字 |

语速口径：**约 360–440 字/分钟（快节奏口播）**——上表每个字数区间都由该口径换算得出。
**700 字 ≈ 1 分 40 秒。**

五层结构：**钩子层 0–8s（45–55 字）/ 铺垫层 8–30s（120–145 字）/ 主体层 30–86s（325–375 字）/ 升华层 86–96s（58–68 字）/ 引导层 96–105s（45–55 字）**，五层合计 593–698 字，天然卡在 700 内。

> ⚠️ **字数上限是硬的，全包统一，没有例外**（2026-09-22 用户拍板：成片太长）。
> 曾经出现过的 `720–880` / `650–850` / 硬上限 `1100` / 每月 1–2 条约 4 分钟长视频等写法**全部取消**；
> 卡上若仍写着旧规格，**一律按 ≤700 执行**，不报冲突、也不放宽。
> **流程开关同样没有例外**：7 张卡原写的「直接出稿」全部取消，统一走「10 选题 × 5 立意 → 用户勾选 → 写稿」。

## 文风硬规范：去 AI 味（2026-09-22 起，全 IP 通用）

字数只是下限要求，**文字本身还得像人说的话**。稿子一旦工整、抽象、四平八稳、每句都对，就会被划走。规范落在 `ip-voice-playbook` 第六节，与五层结构同级：

| 维度 | 硬要求 |
|---|---|
| **句子** | 长句拆短、长短句交错；**输出不要一句一段**，也不要通篇对仗的排比体；允许轻微保留不完美感，别像标准答案 |
| **语态** | 少用被动语态，多用主动表达；不背套话连接词（首先 / 其次 / 综上所述 / 不难发现） |
| **用词** | 减少空泛抽象词，换成具体、生动的表达（能看见的东西、具体的名与数） |
| **视角** | 把「我」从主角位撤下来——只留钩子设问和结尾 CTA；禁「我觉得 / 我认为 / 在我看来」 |
| **开头** | **必须是爆款开头**：第一句就有冲突或反差，抓眼球、立刻留人；第一句不含「我」，钩子层 ≤35 字 |
| **中段** | 言之有理 + 动之以情：每个判断后面跟得住依据；每 2–3 句落一个观众认得出来的具体画面，和观众产生共鸣 |
| **结尾** | 先总结收住（金句要能单独截图）→ 再升华主题 → 最后递一个当天能做的动作；**必须有一句互动或 CTA 口号** |

交稿前必答「去 AI 味五问」：像不像 PPT 上的字 / 有没有「我」在讲课 / 有没有念不完的长句 / 抽象词能不能换具体 / 金句能不能单独截图。
